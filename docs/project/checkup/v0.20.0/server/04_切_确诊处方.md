# 后端确诊与处方（切）

日期：2026-05-14　版本：v0.20.0

## 确诊方法

针对望（结构统计）、闻（静态分析）、问（代码审查）三步发现的疑似问题，逐一深入确认：
- 结构问题 → 打开具体文件，确认是否真的需要拆分
- clippy warning → 判断是代码风格还是潜在 bug
- 设计问题 → 评估影响范围和修复代价

## 健康评估

**整体评分：8.0 / 10**

后端架构设计优秀：
- 模块划分清晰，无循环依赖
- 依赖方向正确（底层 → 上层）
- 已有统一错误类型 `AppError`，只是执行不彻底
- `MessageBroadcaster` trait 解耦了消息层和 WS 层，设计良好
- 事务使用正确（create_group、create_relation 等关键操作都有事务）
- seq 生成器用 `ON CONFLICT DO UPDATE` 保证原子性

主要问题是"规范执行不彻底"——`AppError` 已经定义好了，但旧代码还在用 `StatusCode`。这是典型的渐进式迁移中的过渡状态，不是设计缺陷。

与前端对比：后端的问题更偏"代码风格统一性"，前端的问题更偏"潜在运行时 bug"。后端无 🔴 严重问题。
