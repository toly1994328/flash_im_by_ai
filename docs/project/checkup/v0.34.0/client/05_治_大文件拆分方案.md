# 大文件治理方案

日期：2026-06-14　版本：v0.34.0

## 治理原则

- View 层只做 UI 构建 + 调用 handler，不写业务逻辑
- 按业务场景拆分 mixin / handler，不是一股脑塞 Cubit
- 每个文件控制在 400 行以内
- handler 持有必要依赖（cubit、dio），职责单一

`logic/handler/` 目录专门放事件响应相关的处理器，与 Cubit mixin（状态管理）区分开：
- **mixin**：直接操作 Cubit state（emit），如发送消息、WS 事件
- **handler**：处理 UI 事件的业务逻辑（不直接 emit），如文件打开、菜单分发

### ChatMenuHandler 设计

```dart
/// 菜单事件分发（logic 层）
/// 统一处理桌面右键 + 移动端长按的 MenuAction
class ChatMenuHandler {
  final ChatCubit _cubit;
  final ChatMediaHandler _media;

  ChatMenuHandler({required ChatCubit cubit, required ChatMediaHandler media})
      : _cubit = cubit, _media = media;

  void handle(Message msg, bool isMe, MenuAction action) {
    switch (action) {
      case MenuAction.copy: _cubit.copyMessage(msg.content);
      case MenuAction.reply: _cubit.setReplyTo(msg);
      case MenuAction.recall: _cubit.recallMessage(msg.id);
      case MenuAction.delete: // emit 确认事件或回调
      case MenuAction.forward: // emit 转发事件
      case MenuAction.pin: _cubit.pinMessage(msg.id);
      case MenuAction.unpin: // ...
      case MenuAction.multiSelect: _cubit.enterMultiSelect(msg.id);
      case MenuAction.openFolder: _media.openFileFolder(msg);
      case MenuAction.saveAs: _media.saveFileAs(msg);
      case MenuAction.report: ReportUserEvent(...).emit();
    }
  }
}
```

## 4. message_bubble.dart（436 行 → 目标 380 行）

### 问题

localData JSON 解析在 `_buildContent()` 和 `_buildBubble()` 各执行一次。

### 方案

提取为类级别的 getter 或在 `build` 顶层计算一次，传给两个方法：

```dart
@override
Widget build(BuildContext context) {
  final (String? cachedPath, String? thumbnailPath) = _parseLocalData();
  // 传给 _buildContent 和 _buildBubble
}

(String?, String?) _parseLocalData() {
  if (message.localData == null) return (null, null);
  try {
    final parsed = jsonDecode(message.localData!) as Map<String, dynamic>;
    return (parsed['path'] as String?, parsed['thumbnail_path'] as String?);
  } catch (_) {
    return (null, null);
  }
}
```
