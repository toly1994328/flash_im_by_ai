## 1. chat_page.dart（987 行）

### 职责单一性 ❌

一个 State 同时承担了 6 类职责：
- UI 构建（骨架屏、消息列表、多选栏、群公告）
- 群成员加载（直接发 HTTP）
- 文件操作（_openFileFolder、_saveFileAs）
- 菜单事件分发（_handleMenuAction × 2 重复）
- 视频/文件缓存与打开（onVideoTap ~70 行）
- 转发消息流程

### 重复代码 ❌

- `membersFetcher` 匿名闭包在 ChatInput 和 ChatInputDesktop 处重复（~10 行 × 2）
- `_handleMenuAction` 和 `_showMessageMenu` 内 switch 逻辑完全重复

### 分层违规 ⚠️

- View 层通过 `context.read<MessageRepository>().dio` 直接发 HTTP（_loadGroupMembers、_reportMessage）

### 错误处理 ⚠️

- `_loadGroupDetail`、`_loadGroupMembers` 空 catch 静默吞异常

## 4. chat_file_mixin.dart（464 行）

### 重复代码 ❌

4 个发送方法（image/video/file/audio）结构高度雷同：
```
校验 → 构建 localMessage → emit → upload → 清进度 → 更新 extra → WS send → timeout
```
差异仅在上传 API 和 extra 构建，可模板方法抽象减少 ~150 行。

### 命名 ⚠️

- `FileSizeExceedException` 同时用于文件大小和音频时长，名称有误导

### 错误处理 ⚠️

- catch 中只 `markFailed(localId)`，异常本身被丢弃无日志
