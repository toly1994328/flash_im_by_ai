# 聊天输入框功能优化 — 功能分析

## 概述

对聊天页底部输入栏进行全面优化：样式改为微信风格、新增 Emoji 表情面板、新增语音消息（按住录音）。目标是提升输入体验，对齐主流 IM 的交互标准。

## 一、交互链

### 场景 1：文本输入与发送

**用户故事**：作为用户，我想在聊天页输入文字并发送，以便和对方沟通。

1. 用户点击输入框，键盘弹起
2. 输入文字后，右侧出现蓝色"发送"按钮
3. 点击发送，消息出现在聊天列表，输入框清空
4. 无文字时，发送按钮隐藏，右侧显示 `+` 号

### 场景 2：Emoji 表情

**用户故事**：作为用户，我想快速插入表情符号，以便让聊天更生动。

1. 用户点击输入框右侧的表情图标 😊
2. 键盘收起，底部弹出 Emoji 面板（常用表情网格）
3. 点击某个表情，插入到输入框光标位置
4. 再次点击表情图标（此时显示为键盘图标），面板收起，键盘弹起

### 场景 3：语音消息

**用户故事**：作为用户，我想发送语音消息，以便在不方便打字时快速沟通。

1. 用户点击输入框左侧的麦克风图标 🎤
2. 输入框区域变为"按住 说话"按钮
3. 用户按住按钮，开始录音，界面显示录音波形动画
4. 松手发送语音消息（显示时长）
5. 按住后上滑，进入"取消发送"区域，松手取消
6. 录音时长 < 1 秒，提示"说话时间太短"，不发送

### 场景 4：更多功能面板

**用户故事**：作为用户，我想发送图片/视频/文件，以便分享多媒体内容。

1. 用户点击 `+` 号
2. 键盘收起，底部弹出功能面板（照片、拍照、视频、文件）
3. 点击某项，打开系统选择器
4. 选择完成后发送

## 二、逻辑树

### 事件流：输入栏状态切换

| 时刻 | 事件 | 处理 | 产生的新事件 |
|------|------|------|-------------|
| T0 | 点击输入框 | 键盘弹起，收起 emoji/more 面板 | — |
| T1 | 输入文字 | 检测 hasText，显示/隐藏发送按钮 | — |
| T2 | 点击发送 | 调用 onSendText，清空输入框 | — |
| T3 | 点击表情图标 | 收起键盘，展开 emoji 面板 | — |
| T4 | 点击 emoji | 插入到输入框光标位置 | hasText 变化 |
| T5 | 点击麦克风 | 切换为语音模式，收起键盘和面板 | — |
| T6 | 按住说话 | 开始录音，显示波形 | — |
| T7a | 松手 | 停止录音，发送语音消息 | — |
| T7b | 上滑松手 | 取消录音，不发送 | — |
| T8 | 点击 + 号 | 收起键盘，展开 more 面板 | — |

### 状态流转

| 实体 | 触发事件 | 前状态 | 后状态 |
|------|---------|--------|--------|
| 输入栏模式 | 点击麦克风 | 文本模式 | 语音模式 |
| 输入栏模式 | 点击键盘图标 | 语音模式 | 文本模式 |
| 底部面板 | 点击表情图标 | 无/more | emoji |
| 底部面板 | 点击 + 号 | 无/emoji | more |
| 底部面板 | 点击输入框 | emoji/more | 无（键盘弹起） |
| 发送按钮 | 输入文字 | 隐藏 | 显示 |
| 发送按钮 | 清空文字 | 显示 | 隐藏 |

## 三、功能编号与网络定位

### 本次新增/改造节点

| 编号 | 功能节点 | 层级 | 简介 |
|------|---------|------|------|
| P-20 | 输入栏样式改造 | 前端业务 | 微信风格：灰色容器、白色输入框、矩形圆角 |
| P-21 | Emoji 表情面板 | 前端业务 | 常用表情网格，点击插入 |
| P-22 | 语音消息输入 | 前端业务 | 按住录音、松手发送、上滑取消 |
| D-10 | 语音消息存储 | 领域 | 后端接收音频文件，返回 URL |

### 前置依赖

| 依赖节点 | 依赖方式 | 是否已有 |
|----------|---------|---------|
| 文件上传接口 | HTTP multipart | ✅ 已有（app-storage 模块） |
| WS 消息发送 | msg_type=4 (AUDIO) | ❌ 需新增 |
| ChatCubit 文件发送 | ChatFileMixin | ✅ 已有 |
| 录音权限 | Android/iOS 权限声明 | ❌ 需新增 |

### 边界接口

| 接口 | 定义方 | 消费方 | 说明 |
|------|--------|--------|------|
| POST /api/upload/audio | app-storage | 前端 | 上传音频文件，返回 URL + 时长 |
| WS ChatMessage (type=4) | im-ws | 前端 | 语音消息的 protobuf 帧 |

## 四、结论

- 开发顺序：P-20（样式）→ P-21（Emoji）→ P-22 + D-10（语音，前后端联调）
- 复杂度集中在语音消息：录音权限、波形动画、上滑取消手势、后端音频存储
- 样式改造和 Emoji 面板是纯前端改动，不涉及后端
- 参考项目 `docs/ref/flash_im-main` 中已有完整实现可参考
