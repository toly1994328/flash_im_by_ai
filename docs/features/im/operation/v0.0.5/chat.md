## 一、需求概述

优化 IM 会话列表的交互操作，支持：置顶会话、免打扰、标记已读、标记未读、删除会话、清空会话。需区分**移动端（触摸优先）**和**桌面端（键鼠优先）**的交互差异。

### 2.2 关键发现

**免打扰（isMuted）**：全链路字段已就绪
- DB 迁移 `20260329_002_conversations.sql` 第 25 行：`is_muted BOOLEAN NOT NULL DEFAULT FALSE`

- 查询 SQL 已 SELECT `is_muted`

- 对 Q7（清空会话）有直接影响

**删除消息弹窗（参考风格）**：

- 移动端：底部弹出 BottomSheet；桌面端：居中 Dialog

### 3.3 Q7: 清空会话的跨端行为讨论

**需求**：清空会话仅影响当前手机端，桌面端保持不变，下次手机打开也不同步回来。

**参考：微信的策略** — 各端独立，删除不同步：
> 微信采用去中心化数据管理，手机左滑删会话 / 清空聊天记录，电脑端完全不受影响。各设备互不干涉，删除操作仅影响当前设备。

**技术问题**：当前 SyncEngine 每次重连做全量覆盖——
```
重连 → HTTP GET /conversations → syncConversations(全量覆盖本地)
```
单纯删本地数据，下次同步就全部回来了。

**后端方案 vs 本地方案对比**：

| 维度 | 后端方案 | 本地 SharedPrefs 方案 |
|------|---------|----------------------|
| 跨端行为 | ❌ 全端同步清空 | ✅ 各端独立（微信同款） |
| 重装/换机 | ✅ 状态持久 | ⚠️ 清空标记丢失 |
| 代码改动 | ~30 行后端 | ~15 行客户端 |
| 架构匹配 | 反微信模式 | ✅ 微信模式 |

**最终决策：本地 SharedPrefs per-conversation 时间戳方案**，理由：
1. 符合微信「各端独立」的用户心智
2. 零后端改动
3. 桌面端天然不受影响

```
SharedPreferences key: 'conv_cleared_at_map' = JSON Map { conversationId: "ISO8601" }

清空时：
  记录 conversationId → DateTime.now().toUtc() 到 JSON Map

消息展示时：
  过滤掉 sent_at < clearedAt 的消息

新消息（创建在 clearedAt 之后）正常显示
桌面端不读这个标记 → 无影响
```

| 维度 | 行为 |
|------|------|
| 手机端清空后 | 该会话预览清空，消息列表只显示清空后的新消息 |
| 新消息到达 | 消息时间 > clearedAt，正常展示 |
| 桌面端 | 完全不受影响，所有消息正常显示 |
| 服务端 | 不调用任何服务端 API，数据零改动 |

> ✅ **已确认**：走本地 SharedPrefs 时间戳方案，不走后端 API。

## 四、功能边界

### ✅ 本次实现

1. **置顶/取消置顶** — 后端新增 toggle API + WS 推送 + 前端 UI（滑动+长按+右键）
2. **免打扰** — 后端新增 toggle API + WS 推送 + 前端 UI（滑动+长按+右键）
3. **标记未读** — 后端新增 `POST /conversations/{id}/unread`（设 unread_count=1）+ 前端长按/右键
4. **删除会话** — 前端补齐 UI 入口（滑动+长按+右键+确认弹窗），后端已有 API
5. **清空会话聊天记录** — 纯本地操作（SharedPreferences per-conversation 时间戳方案），不走后端
6. **置顶排序** — 列表分置顶区 + 普通区，置顶区按 `pinned_at` 倒序
7. **滑动菜单** — 移动端 Slidable，4 个按钮（置顶、免打扰、标为已读、删除）
8. **长按菜单** — 移动端 BottomSheet，全功能选项
9. **右键菜单** — 桌面端 ContextMenu，全功能选项
10. **WS 实时推送** — 置顶/免打扰状态变更时实时通知所有端

### ❌ 本次不做

1. 拖拽排序置顶项
2. 批量选择删除
3. 清空聊天记录的跨端同步（纯本地）
4. 免打扰的消息通知屏蔽逻辑（本次只做 UI 标记开关，后续版本再做通知过滤）
