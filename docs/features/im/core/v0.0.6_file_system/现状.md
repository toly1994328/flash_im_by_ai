# 文件存储系统现状

## 后端存储架构

模块：`server/modules/app-storage/`

### 目录结构

```
uploads/
├── original/{YYYY/MM}/{uuid}.{ext}    # 原图（jpg/png/gif/webp）
├── thumb/{YYYY/MM}/{uuid}.webp        # 图片缩略图（长边≤400px，WebP）
├── thumb/{YYYY/MM}/{uuid}.jpg         # 视频封面（客户端上传）
├── video/{YYYY/MM}/{uuid}.{ext}       # 视频（mp4/mov/avi）
└── file/{YYYY/MM}/{uuid}.{ext}        # 通用文件
```

### 配置

| 项目 | 值 |
|------|-----|
| 图片大小上限 | 10MB |
| 视频大小上限 | 50MB |
| 文件大小上限 | 50MB |
| 缩略图长边 | 400px |
| 缩略图质量 | 80 |
| 缩略图格式 | WebP |

### 文件命名

每次上传生成新 UUID v4 作为文件名，与原文件名无关。

### URL 格式

```
/uploads/original/2026/06/{uuid}.jpg
/uploads/thumb/2026/06/{uuid}.webp
/uploads/video/2026/06/{uuid}.mp4
/uploads/file/2026/06/{uuid}.pdf
```

通过 `tower-http` 的 `ServeDir` 静态文件服务对外提供访问。

## 前端文件缓存

模块：`client/modules/flash_im_cache/`

### 缓存策略

| 类型 | 缓存时机 | 存储位置 |
|------|----------|----------|
| 图片 | 通过 CachedNetworkImage（PersistentCacheManager） | Application Support/mediaxPersistentCache |
| 视频 | 点击播放时下载（FileCacheManager） | 应用缓存目录 |
| 文件 | 点击查看时下载（FileCacheManager） | 应用缓存目录 |
| 音频 | 自动缓存 | 应用缓存目录 |

### localData 结构

消息的 `localData` 字段存储本地缓存信息（JSON）：

```json
// 图片/文件/音频
{"path": "/data/.../file.mp4", "cached_at": 1718500000000}

// 视频（含封面）
{"path": "/data/.../video.mp4", "thumbnail_path": "/data/.../thumb.jpg", "cached_at": 1718500000000}
```

## 已知问题

### 1. 无去重机制

同一文件多次发送 → 服务端存多份。浪费磁盘。

**影响**：
- 转发图片/视频 = 重新上传一份
- 同一张图片发给 10 个人 = 存 10 份
- 无法"秒传"

### 2. 无文件引用计数

删除消息时文件不会被清理。磁盘只增不减。

### 3. 无存储配额

单用户可无限上传，没有容量限制。

### 4. 无清理策略

- 服务端无过期清理
- 客户端缓存无大小上限（PersistentCacheManager stalePeriod=365天）

### 5. 视频不走缓存复用

两条不同消息引用同一视频 URL，客户端会各自下载一次。

---

## 下一步方向

1. **文件去重（秒传）** — 上传前客户端算 hash，服务端查重，已有则直接返回 URL
2. **引用计数** — 文件被消息引用的次数，归零可清理
3. **存储配额** — 按用户/群限制上传总量
4. **客户端缓存管理** — 大小上限 + LRU 清理
